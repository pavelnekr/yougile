# YouGile Operations Portal

Внутренний портал для управления назначениями инженеров на площадки в YouGile.
Оператор загружает XLSX-план или выбирает площадки в портале, сверяет
предпросмотр и явно подтверждает изменение. Назначения, снятия и отправка
комментариев выполняются через API YouGile, а результат каждой операции
сохраняется в PostgreSQL.

## Возможности

| Раздел | Возможности |
| --- | --- |
| Обзор | Состояние сервисов и быстрый переход к рабочим сценариям |
| Площадки (`/sites`) | Просмотр активных задач плана YouGile |
| Назначение (`/assign`) | Выбор площадок и инженера, предпросмотр текущих назначений, подтверждение и фоновое выполнение |
| Снятие (`/remove`) | Выбор строк XLSX, предпросмотр ответственных и фоновое снятие выбранных инженеров |
| Комментарий (`/comment`) | Предпросмотр и отправка комментария в чаты выбранных задач |
| Проверка работ (`/work-check`) | Просмотр последних сообщений в чатах задач по строкам XLSX |
| Аудит (`/audit`) | История загрузок XLSX, содержимое исходных строк и выгрузка проблемных строк |
| История (`/history`) | Сводная аналитика и журнал операций |
| Настройки (`/settings`) | Шаблоны комментариев для разных видов работ |
| Учётные записи (`/admin/users`) | Управление пользователями, доступом, паролями и личными токенами YouGile; доступно администраторам |

Разделы имеют прямые URL: ссылку можно открыть в новой вкладке или после
перезагрузки. Пункт меню учётных записей доступен только администраторам;
API отдельно проверяет роль.

### Учётные записи и доступ

- Вход использует серверные cookie-сессии; пароли хранятся в виде хешей.
- Самостоятельная регистрация создаёт пользователя с ролью `OPERATOR` и работает,
  только если задан `REGISTRATION_KEY`. Администратор также может создать
  учётную запись в интерфейсе.
- Роли в модели: `ADMIN`, `OPERATOR`, `VIEWER`. Управление учётными записями
  ограничено ролью `ADMIN`; доступ к рабочим API требует действующую сессию.
- Администратор может отключить пользователя, поменять его роль или пароль.
  Отключение и смена пароля завершают его сессии. Нельзя отключить себя,
  поменять собственную роль или убрать последнего активного администратора.
- Каждому пользователю администратор задаёт личный токен YouGile. Перед
  сохранением токен проверяется; в базе он хранится в зашифрованном виде
  (AES-256-GCM), а его значение после сохранения не отображается. Без
  настроенного личного токена пользователь не может обращаться к YouGile.

### XLSX и рабочие операции

- План должен содержать столбцы с номером площадки (`id_site`) и инженером
  (`user`). Распознаются также распространённые английские и русские варианты
  заголовков. Обрабатывается первый лист; в нём допускается до 5 000 строк
  плана. Максимальный размер загружаемого файла по умолчанию — 10 МБ.
- Номера площадок сопоставляются с активным планом YouGile, имена инженеров —
  с пользователями YouGile. Неизвестные и неоднозначные совпадения, дубликаты
  и некорректные строки показываются как проблемы импорта.
- Перед записью состояние задач перечитывается из YouGile; загрузка файла сама
  по себе ничего не меняет. Назначение, снятие и отправка комментариев требуют
  отдельного подтверждения после предпросмотра.
- К одной операции можно включить до 2 000 площадок. Внутри назначения и снятия
  запросы выполняются последовательно; очередь фоновых операций также
  обрабатывает за раз только одну операцию. При HTTP 429 запрос назначения или
  снятия повторяется после ожидания 60 секунд, пока YouGile возвращает 429.
- При назначении по XLSX можно выбрать вид работы: фильтры, балансеры, байпасы
  или EHW. Шаблоны комментариев хранятся в настройках, ограничены 10 000
  символами и поддерживают `${data}` и `${time}` из исходных колонок XLSX.
- Для операций сохраняются общий статус и результат по каждой площадке.
  Страница операции опрашивает API, пока она выполняется, и показывает итог.
- Портал хранит последние пять загрузок XLSX. Более старые батчи и их строки
  удаляются при новой загрузке; уже созданная операция хранит собственные
  данные и от этого не прерывается.

### Границы текущей реализации

- Отдельный экран аудита расхождений назначений и импорт старых таблиц из n8n
  пока не реализованы.
- Журнал действий администраторов доступен в логах API, но не выведен в
  интерфейс.
- Статус YouGile в `/api/health` отражает наличие хотя бы одного активного
  пользователя с настроенным токеном; это не проверка доступности внешнего API
  YouGile.

## Архитектура

```text
apps/
  api/                 Fastify 5, Prisma, интеграция YouGile и BullMQ worker
    prisma/            схема PostgreSQL и миграции
    src/
      integrations/    YouGile HTTP-клиент и шифрование токенов
      jobs/            очередь и последовательный обработчик операций
      modules/         auth, admin, sites, imports, assignments, comments,
                       history, settings, users, audit
  web/                 React 18 + TypeScript + Vite 6
packages/
  shared/              пакет общих типов
```

- **PostgreSQL** хранит учётные записи, сессии, загрузки XLSX, настройки,
  операции и их результаты.
- **Redis + BullMQ** используются для очереди операций. Worker работает в
  процессе API; отдельный сервис worker не нужен.
- **YouGile** — источник актуального состояния задач и пользователей. Все
  HTTP-запросы к YouGile проходят через общий клиент API; токен берётся из
  учётной записи автора действия.
- Web обращается к API только по относительным адресам `/api/...`; в разработке
  запросы проксируются Vite, в production — nginx.

Основные технологии: Node.js 20+, TypeScript, Fastify 5, React 18, Vite 6,
Prisma 6, PostgreSQL 16, Redis 7, BullMQ, ExcelJS и Zod.

## Локальный запуск

Нужны Node.js 20 или новее, npm и Docker Compose. В корне репозитория:

1. Создайте `.env` на основе `.env.example` и задайте значения для своей среды.
   `.env` содержит секреты и не должен попадать в Git.
2. Установите зависимости и подготовьте Prisma Client:

   ```bash
   npm install
   npm run db:generate
   ```

3. Запустите PostgreSQL и Redis:

   ```bash
   docker compose up -d postgres redis
   ```

4. Создайте таблицы и миграции:

   ```bash
   npm run db:migrate
   ```

5. Создайте первую учётную запись администратора. Скрипт запросит данные,
   если запустить его без аргументов:

   ```bash
   npm run user:create --workspace @portal/api
   ```

6. Запустите API и web:

   ```bash
   npm run dev
   ```

   Web: <http://localhost:5173>; API: <http://localhost:4000>.
   Для проверки состояния API откройте <http://localhost:4000/api/health>.
   После входа администратор добавляет личный токен YouGile в разделе
   «Учётные записи».

Остановите dev-процесс сочетанием Ctrl+C, инфраструктуру — командой
`docker compose stop`. Команда `npm run dev` запускает web и API вместе;
не запускайте параллельно отдельный web на том же порту.

### Вариант: web в dev-контейнере

Для горячей перезагрузки web из Docker Desktop:

```bash
docker compose up -d postgres redis web-dev
npm run dev --workspace @portal/api
```

Откройте <http://localhost:5173>. Dev-контейнер проксирует `/api` к API на
хосте через `host.docker.internal`.

## Переменные окружения

Все переменные API валидируются при запуске; значения по умолчанию и локальный
шаблон находятся в `.env.example`.

| Переменная | Назначение |
| --- | --- |
| `NODE_ENV` | Режим приложения |
| `API_PORT` | Порт API; по умолчанию `4000` |
| `WEB_ORIGIN` | Origin web для CORS и cookie-сессий |
| `DATABASE_URL` | Подключение Prisma к PostgreSQL |
| `REDIS_URL` | Подключение очереди к Redis |
| `JWT_SECRET` | Секрет приложения, не короче 32 символов |
| `REGISTRATION_KEY` | Ключ самостоятельной регистрации; пустое значение выключает её |
| `YOUGILE_API_URL` | Базовый URL API YouGile, например `https://yougile.ru/api-v2` |
| `YOUGILE_TOKEN_ENCRYPTION_KEY` | Ключ шифрования пользовательских токенов: ровно 64 hex-символа |
| `YOUGILE_PLAN_COLUMN_ID` | UUID колонки плана YouGile |
| `UPLOAD_MAX_BYTES` | Максимальный размер XLSX в байтах; по умолчанию 10 МБ |
| `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` | Настройки PostgreSQL в production Compose |
| `WEB_PORT` | Порт production web на хосте |

Сгенерируйте ключ шифрования командой `openssl rand -hex 32` (или эквивалентным
криптографически стойким генератором). **Сохраните его в защищённой резервной
копии и не меняйте, пока в базе есть зашифрованные токены:** без исходного ключа
они не расшифровываются. Не используйте ключ из примера как production-секрет.

В production `DATABASE_URL` и `REDIS_URL` внутри контейнеров формируются
Compose из настроек сервисов; не заменяйте их локальными адресами хоста.

## Сборка, миграции и развёртывание

```bash
npm run build
```

Команда генерирует Prisma Client и собирает API и web. Локальная миграция:

```bash
npm run db:migrate
```

Для production-развёртывания используйте [DEPLOY.md](./DEPLOY.md). Compose-файл
`docker-compose.prod.yml` запускает PostgreSQL, Redis, миграцию Prisma, API и
web; миграция выполняется до старта API:

```bash
docker compose -f docker-compose.prod.yml up -d --build
```

Проверить контейнеры и логи можно командами:

```bash
docker compose -f docker-compose.prod.yml ps
docker compose -f docker-compose.prod.yml logs -f api
```
